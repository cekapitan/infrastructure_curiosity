## Bring these to the team

### 1. S3 can transition immediately to Standard-IA or One Zone-IA

AWS removed the previous 30-day wait before S3 Lifecycle can transition a new object from S3 Standard into Standard-IA or One Zone-IA. This could remove avoidable Standard storage time for backups, logs, and compliance objects known to be cold when written.

The catch is economic, not syntactic: minimum billable object sizes and storage durations still apply, retrieval costs remain, and One Zone-IA has a different resilience profile. Start with an inventory of cold-on-arrival prefixes and model real size, retention, and retrieval behavior.

- Evidence: [AWS announcement, 2026-07-16](https://aws.amazon.com/about-aws/whats-new/2026/07/s3-removes-30-day-transitions-standard-ia-one-zone-ia/)
- Repository record: [aws-s3-same-day-ia.json](../../discoveries/aws-s3-same-day-ia.json)
- Test-only example: [examples/aws/s3-same-day-ia](../../examples/aws/s3-same-day-ia/)

This item was found by the first-party release-feed cross-check, not the social discovery run. That miss is why future runs require both inputs.

### 2. Cost alarms need independent corroboration and containment

AWS acknowledged inaccurate Cost Explorer estimated billing data that produced erroneous AWS Budgets and Cost Anomaly Detection alerts. The lesson is not to distrust cost alerts; it is to avoid treating one provider-derived estimate as an enforcement boundary.

Review which independent signals still work during a billing-data incident: request or token counts, storage growth, queue depth, service quotas, concurrency caps, workload-level rate limits, and a documented validation/escalation path.

- Evidence: [AWS Weekly Roundup, 2026-07-20](https://aws.amazon.com/blogs/aws/aws-weekly-roundup-one-click-lambda-setup-prompt-openai-gpt-5-6-models-on-bedrock-and-more-july-20-2026/)
- Repository record: [aws-cost-estimate-incident.json](../../discoveries/aws-cost-estimate-incident.json)

### 3. KMS multi-Region keys are useful, but not new and not one global resource

The seed idea for this repository was KMS multi-Region keys. AWS launched them on 2021-06-16, so this brief deliberately labels the capability **established**. A primary and its replicas share key material and an ID, which is useful for specific client-side encryption, cross-Region signing, active-active, and disaster-recovery requirements.

The regional control plane remains real: policies, grants, aliases, tags, descriptions, and enabled state do not become global. Terraform still declares the primary and each replica. Adopt only for a requirement that justifies the extra policy and lifecycle surface.

- Evidence: [AWS launch announcement, 2021-06-16](https://aws.amazon.com/about-aws/whats-new/2021/06/kms-multi-region-keys/)
- Repository record: [aws-kms-multi-region.json](../../discoveries/aws-kms-multi-region.json)
- Test-only example: [examples/aws/kms-multi-region](../../examples/aws/kms-multi-region/)

### 4. Watch persistent cloud workspaces for coding-agent teams

Conductor Cloud is a current tool-side signal: persistent isolated microVM workspaces, multiplayer access, share links, and an API. That moves agent execution and source state beyond a laptop worktree and makes identity, secret isolation, egress, audit, retention, incident response, and per-workspace cost part of the evaluation.

This is a watch item, not an endorsement. Require evidence for those controls before a pilot carries sensitive code or credentials.

- Evidence: [Conductor changelog, 2026-07-30](https://www.conductor.build/changelog)
- Repository record: [conductor-cloud-workspaces.json](../../discoveries/conductor-cloud-workspaces.json)
